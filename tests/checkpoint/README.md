# نقطة حفظ سجلّ المراجعات (فرع log-checkpoint — غير مدموج وغير منشور)
- core.js: replayLog (حلقة econ نفسها، مستخرجة بلا تغيير)، ckState، ckFold. عند تجاوز 60000 حدث تُطوى أيام كاملة قديمة حتى يبقى نحو 50000.
- نقطة الحفظ CK في وثيقة مستقلة users/{uid}/data/ck تُكتب عند الطيّ فقط، وتُرسل للتطبيق فقط حين تختلف (ckt).
- إصلاح مرافق: الخادم الحالي لا يحفظ وثيقة السجل حين يبلغ 60000 (الطول ثابت)، فتضيع المراجعات الجديدة. صار يحفظها إن تغيّر الطول أو أول حدث أو آخره.
- حذف المشرف بيانات حساب يمسح نقطة الحفظ أيضًا. النسخ الاحتياطية تشملها (كل وثائق data).
الاختبارات:
- run.sh [سنوات]: محاكاة بنشاط مرتفع، مقارنة بالمرجع (main بلا حدّ للسجل) في كل شهر، مع حفظ وإعادة تحميل أسبوعيًا وتغيير جهاز شهريًا. VOCAB=8000 لعدد كلمات واقعي.
- integration.mjs وlog-at-cap-bug.mjs: بشيفرة الخادم الحقيقية — تُشغَّل بـrun-it.sh (القديم = PRE_FOLD).
