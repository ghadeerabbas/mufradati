# الإصدار 1 — خطة النشر على النسخة الأساسية (لم يُنفَّذ شيء)

ثلاثة حسابات حقيقية فقط. لا بيئة اختبار مستقلة. كل خطوة نشر بموافقة صريحة.

## الفروع
- backup-tools: main + أدوات النسخ الاحتياطي فقط (لا تغيير في أي قاعدة، core.js نفسه).
- release-1: backup-tools + إصلاح مهمة البازل + أرشيف المكافآت + حدّ المنافسين الآليين + نقطة حفظ السجل + آلية رقم النسخة.
- rollback-r1: إصدار التراجع الآمن = backup-tools + أرشيف المكافآت + نقطة حفظ السجل (بلا إصلاح المهمة والمنافسين ورقم النسخة).

## الخطوة أ: أدوات النسخ (backup-tools) — موافقة 1
1. دمج backup-tools في main ← ينشر الموقع والخادم تلقائيًا. لا تغيير في الحسابات.
2. من «الحماية» في حساب المشرف: «نسخة الآن» ← «تحقق كامل» على النسخة (يجب: مطابقة لكل الحسابات) ← «تنزيل» (يُحفظ الملف في الهاتف والحاسوب) ← «لقطة الحسابات» ← «تنزيل اللقطة».
3. يُرسل ملف اللقطة لي للتوثيق (أرقام فقط، بلا كلمات مرور).

## الخطوة ب: الإصدار 1 — موافقة 2
1. وقت هادئ، لا يوم الإثنين، ولا أحد يدرس (رسالة للعائلة).
2. نسخة جديدة ← تحقق كامل ← تنزيل ← لقطة («قبل»).
3. دمج release-1 في main بدفعة واحدة ← يُنشر الموقع (GitHub Pages) والخادم (Cloudflare) معًا خلال دقيقتين تقريبًا.
4. لا APK: التطبيق يفتح الموقع ويأخذ النسخة الجديدة تلقائيًا. APK جديد يلزم فقط لتغيير غلاف Android، وهذا الإصدار لا يغيّره.
5. mufradati1 يبقى على نسخته حتى يُحدَّث design بالإصدار 1 (موافقة 3). لا يُستعمل حتى ذلك الحين.

## بعد النشر مباشرة (10 دقائق)
1. سير «نشر الخادم» في GitHub Actions ناجح.
2. فتح التطبيق بكل حساب ← تحديث تلقائي مرة واحدة إن لزم ← لا شريط تحديث بعدها.
3. لقطة الحسابات «بعد» ← مقارنة باللقطة «قبل»: الجواهر والخبرة والمستوى والسلسلة والكلمات والمحطات والصناديق والتحديات والدوري والبازل والإنجازات كلها مطابقة (folded = 0).
4. في حساب واحد: مراجعة كلمة ← تزداد الخبرة وتُحفظ بعد إعادة الفتح.
5. محطة بلا خطأ مع تدريبها ← «مهام اليوم» 1/1 ← فتح الصندوق ← قطعة ← إغلاق التطبيق وفتحه: 1/1 «✓» والقطعة باقية ← لا صندوق ثانٍ.
6. الدوري: لا منافس آلي بصفر خبرة، ومركزك كما يعرضه التطبيق.
7. جهاز ثانٍ لنفس الحساب: الأرقام نفسها.
8. «الحماية»: لا أخطاء جديدة.

## التراجع
- القاعدة: لا رجوع إلى شيفرة تحذف من السجلّات دون طيّ بعد أن يبدأ الطيّ.
- اللقطة تعرض «مطويّ في الأرشيف» لكل حساب:
  - 0 لكل الحسابات (المتوقّع لأشهر): التراجع إلى main آمن تمامًا (revert للدمج). الحقول الجديدة تبقى في البيانات وتتجاهلها النسخة القديمة، وتعود عند إعادة النشر.
  - أكبر من 0: التراجع إلى rollback-r1 فقط (يقرأ الأرشيف ونقطة الحفظ)، ثم إصلاح المشكلة بنسخة جديدة.
- مشكلة في إصلاح المهمة أو المنافسين أو رقم النسخة وحدها: rollback-r1.
- الاسترجاع من نسخة احتياطية آخر حلّ: يمحو ما بعد النسخة. يُفرّغ الآن نقطة الحفظ التي لم تكن في النسخة.
